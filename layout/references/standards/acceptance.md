# 验收标准与回归场景

## 可以机器确认

- Skill frontmatter/name 合法、内部 Reference 路径存在。
- 原文锁定：source/txt/ZIP 字节相等，HTML 解码相等；只改正文时 PNG 哈希不变。
- 字体/图片加载和文字边界通过；ZIP 可以解压、图片数量尺寸正确。

## 需要编辑判断/用户审阅

观点是否来自作者；原语气是否保留；是否出现自拟金句或硬 CTA；手机缩略图的重点、原图裁切、间距层次。技术 QA 不能判定 taste，也不能把用户未审阅写成已通过。

## 五个现实场景

| 输入 | 预期行为 | 失败迹象 |
|---|---|---|
| “这是最终原文，不要润色” | 原样保存，更新指定载体 | 改了空格、补标题或结尾 |
| “稍微压缩，保留我的语气” | 去重复，保留判断和具体观察 | 生成没说过的行业建议 |
| “图不用动，只更新正文和包” | PNG 哈希不变 | 顺手重排全部图 |
| “另一位作者要用” | 换档案与素材；沿用制作标准 | 把原作者经历写成对方经历 |
| “蓝白黑不变，第2页太空” | 只调整该页内容关系 | 换色、加无关装饰或通篇增字 |

当前原文同步脚本应以含中文、空白、HTML 字符、反引号与 `${}` 的小样本验证转义与不执行代码；真实稿再核对字节。其余场景作为以后真人使用的回归清单，不虚报为已做独立 Agent 评测。不要为几条 Markdown 规则启动批量模型任务。

## 视觉落实检查

- 蓝白黑与思源黑体实际加载，不能只在说明里写到。
- 标题有居中、左右、下沉的阅读变化；相关内容聚合，不用无关装饰填空。
- UI 阴影、描边、圆角和重叠体现前后关系，主次清楚；粘土点缀是可选项，不强行添加。
- 图标语义对应内容，来源链接与许可可找到；检查真实 SVG 配色和缩放。
- Reference 配方、模板已实现、成图已使用、用户已认可分别记录，不能互相替代。

## 多比例验收

每种比例检查对应逻辑尺寸和2倍PNG，标题断行、卡片列数和阅读顺序应重排。Playground切换后URL、画布和导出链接对应同一比例；缩略图与页数一致；全屏退出可用。
